# 11 — 决策记录（Decision Log）

> 本文档记录产品与架构的关键决策及其理由，供交付团队理解「为什么这么定」。新增决策追加在末尾。

## 架构与范围

| # | 决策 | 理由 |
|---|---|---|
| D1 | **单组织自部署**，Workspace 退化为单一固定实例，不做多租户 | 面向一个公司内部；避免多租户复杂度。未来需要再统一加 `tenant_id` |
| D2 | **共享服务账号**连接模型（少量 DB 账号，平台侧做权限校验） | 实现简单、权限在平台掌控；代价：DB 侧审计只见平台身份（以平台审计为准） |
| D3 | （v2）敏感列标注与脱敏规则延后 | v1 不做应用层脱敏（见 D32）；敏感列可见性由数据库授权决定 |
| D4 | **仅实现 PostgreSQL，原生实现，不预设多引擎插件抽象** | 聚焦、避免 Oracle 驱动授权等坑；不为第二个引擎提前抽象，未来按需再抽取 |
| D13 | **不分阶段**，一份完整 PRD | 整体作为一个产品交付（无 Phase 1/2 拆分） |

## 明确不做（产品边界）

| # | 决策 | 理由 |
|---|---|---|
| D11 | **不做行级权限** | SQL 改写注入正确性风险高、bug=安全事故；未来走数据库原生 RLS |
| D12 | **不做数据库变更管理**（DDL 审批/迁移/SQL Review） | 本期只做查询/导出；架构预留任务执行器与审批抽象 |
| D6 | 不做定时导出/订阅 | 需求未明确 |
| D7 | 不做敏感操作 step-up 二次认证 | 需求未明确；v1 无 JIT/审批流，如需后加 |
| D9 | 不做网络层 IP 准入 | 需求未明确 |
| D10 | 不做「查询结果」分享（只分享 SQL 文本） | 结果分享脱敏责任不清、风险高 |

## 资源与隔离模型

| # | 决策 | 理由 |
|---|---|---|
| D15 | **Instance 下放到 Project**（归属项目，团队自治）；新增 `projectDBA`，移除 `workspaceDBA` | 公司实例不跨团队共享；实例/库由项目角色管理，无需平台 DBA |
| D16 | **Database 的项目归属由其实例决定**（不在 database 表冗余 project_id） | 单一事实来源；新发现库自动归属实例所在项目，无需手动分配/转移 |
| D17 | **环境为一等策略维度**（`environment_policies` 驱动访问控制/查询导出护栏） | 同一查询 prod 严、dev 宽；环境不只是标签 |

## 收藏与分享

| # | 决策 | 理由 |
|---|---|---|
| D18 | 收藏指向 Worksheet；**分享只传递 SQL 文本、不传递数据权限** | 执行按接收者本人权限校验，分享者无法借 SQL 越权 |

## 审计与安全

| # | 决策 | 理由 |
|---|---|---|
| D5 | **审计 SQL 按字面量原样记录**（含 PII，不做参数化） | 完整支持事后回溯/取证；代价：审计本身是敏感对象，需收紧读权限 |
| D25 | **凭据应用层 AES-256-GCM 加密**，主密钥从环境变量/KMS 注入；支持 `secret_ref` 对接外部 Secret Manager（可选） | 默认能跑；高安全场景可接 KMS/Vault |
| D26 | **审计读权限**：`securityAdmin`/`workspaceAdmin` 可读全部；`projectOwner` 可读**本项目**审计 | 团队可自查本项目操作；跨项目不可见 |
| D8 | **不做 EXPLAIN 成本护栏**，以语句超时 + 行数/字节上限保护业务库 | PostgreSQL cost 为任意单位，作为阈值既误杀又漏放；超时+上限更可靠 |

## 工程与运营（本轮确认）

| # | 决策 | 理由 |
|---|---|---|
| D19 | Schema 同步：**定时 15min + 手动触发 + 懒刷新**（缓存失效后台异步刷新，查询先用旧值） | 平衡新鲜度与业务库压力 |
| D20 | 导出产物：**本地盘 + 存储抽象**（封装存储接口，未来可切 S3/OSS） | MVP 简单，避免日后返工；数据模型 `export_archives(storage,location)` 已预留 |
| D21 | **站内通知中心**（导出完成）；MVP 不做邮件 | 简单可控；邮件后续可加 |
| D22 | 预估 **>1 万行强制异步导出**（EXPLAIN 估算） | 保护同步请求；小结果可直接下载 |
| D23 | **中英双语 i18n**（MVP 都出） | 团队要求 |
| D24 | **平台单节点、当前版本不做备份** | 验证期可用性优先；上线前补 pg_dump 备份。关联风险见 D-risk-1 |

| # | 决策 | 理由 |

## 本轮精简（v1 实用优先）

> 本轮按"实用优先、不过度设计"原则，对 PRD 做了一次精简（同时修订了 D4、D8）。下列为新增决策；延后项的 v2 设计方向统一见 [18 路线图](./18-roadmap.md)。

| # | 决策 | 理由 |
|---|---|---|
| D32 | **v1 不做应用层动态脱敏 / 谓词列保护（QuerySpan）/ 脱敏豁免**，延后 v2 | 该能力安全攸关、实现重（解析器 bug = 数据泄露）；v1 敏感列可见性由数据库授权（GRANT）决定 + 全量审计。本轮采纳最轻路径 |
| D33 | **JIT 临时去脱敏访问延后 v2**（随 D32） | JIT 主要用途是临时去脱敏，与脱敏绑定；v1 临时放行由 DBA 调整授权 + 审计实现 |
| D34 | **数据级授权条件改"结构化字段"（环境/库/表），不引入 CEL 作为对外策略语言** | 授权维度固定可枚举；CEL 暴露给非工程师易误配=越权。cel-go 不引入 |
| D35 | **不做自定义角色**（v1 仅预置角色） | 8 个预置角色已覆盖；自定义角色的 CRUD/权限子集/审计成本不值得 |
| D36 | **收藏/分享简化**：收藏即星标；可见性 PRIVATE/PROJECT；延后 folder/pin/note、ShareLink token、PROJECT_WRITE/LINK | 效率功能非安全核心；项目可见性已覆盖团队共享 |
| D37 | **认证/导出多项延后 v2**：Service Account/PAT、OAuth2、邮箱验证码登录、XLSX、SQL(INSERT) 导出格式 | 产品面向自然人查询/导出；CSV/JSON + OIDC/LDAP + 本地账号已够；按需再加 |
| D38 | **API 契约以 OpenAPI 3（HTTP/JSON）为唯一事实来源**，不预设后端语言/框架 | 满足「编程语言无关」要求；权限/审计以 `x-` 扩展声明，任何语言都能实现 |
| D39 | **查询结果用 unary + keyset 游标分页**，不用 gRPC server-streaming | 与 HTTP/JSON 主契约一致；多语句结果集按语句分页，实现更简单通用 |
| D40 | **导出 ZIP 密码仅用户自设**，平台不存储、不下发；下载时流式解密校验 | v1 无安全密码下发通道；避免产物密码落入审计/通知等不可控路径 |
| D41 | **手动 Schema 同步即时返回（202 + 当前 sync_status），后台异步执行**；不引入 LRO/Operation 轮询 | 同步非实时、可耗时；懒刷新模型已接受即时返回；减少契约复杂度 |

## 技术选型（详见 [19-tech-stack.md](./19-tech-stack.md)）

| # | 决策 | 理由 |
|---|---|---|
| D42 | **后端语言使用 Go 1.23+** | 静态类型、pgx/v5 驱动成熟、单二进制部署、并发模型适合查询/导出/同步任务 |
| D43 | **HTTP 框架使用 chi** | 标准库风格、轻量、中间件链清晰，适合认证/ACL/审计横切层 |
| D44 | **API 以 OpenAPI 3 手写契约，用 ogen 生成服务端/客户端** | 满足语言无关要求；强类型、契约一致性；权限/审计以 `x-` 扩展声明 |
| D45 | **数据库访问使用 pgx/v5 + bun** | pgx 是 Go 最佳 PG 驱动；bun 是轻量类型安全查询构建器，适合 v1 快速迭代 |
| D46 | **v1 任务队列使用进程内 Runner，预留抽象，v2 可切 Redis + asynq** | v1 零外部依赖、单节点足够；抽象防止返工 |
| D47 | **前端使用 React 19 + Vite 6 + Tailwind CSS + shadcn/ui** | 复杂工作台生态成熟、构建快、可定制、Bytebase 已验证 |
| D48 | **monorepo 采用简单目录结构，不用 Turborepo/nx** | v1 应用/包少，收益不明显；保留未来引入 Turborepo 的扩展性 |
| D49 | **v1 部署方式使用 Docker Compose** | 单组织自部署最友好，避免 K8s 复杂度；未来可迁移到 Helm |
