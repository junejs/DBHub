# 01 — 系统架构

## 1. 总体架构

系统采用单体优先（modular monolith）架构，前后端分离。v1 面向 PostgreSQL，核心逻辑原生实现。

```
┌─────────────────────────────────────────────────────────────────┐
│                        客户端（Web UI）                          │
│   SQL 工作台（Monaco + LSP over WS） · 资源浏览 · 导出 · 审计   │
└──────────────────────────┬──────────────────────────────────────┘
                           │ HTTPS (HTTP/JSON) / WebSocket(LSP)
┌──────────────────────────▼──────────────────────────────────────┐
│                       API 网关层（Gateway）                      │
│   认证拦截器 · 审计拦截器 · ACL 拦截器 · 限流 · 会话             │
└──────────────────────────┬──────────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────────┐
│                         API 服务层（Services）                   │
│  Instance · Database · SQL · Export · IAM · Audit · IDP · User  │
└──┬───────────┬───────────┬───────────┬───────────┬─────────────┘
   │           │           │           │           │
   ▼           ▼           ▼           ▼           ▼
┌──────┐  ┌────────────┐  ┌─────────┐ ┌────────┐  ┌──────────┐
│ 权限 │  │ SQL 解析   │  │ 任务    │ │ 元数据 │  │   ...    │
│ 引擎 │  │ /补全(PG)  │  │ 调度    │ │ 同步器 │  │          │
│(IAM) │  │(Parser)    │  │(Runner) │ │(Syncer)│  │          │
└──────┘  └─────┬──────┘  └─────────┘ └────────┘  └──────────┘
                │
                ▼
         ┌─────────────┐
         │ PostgreSQL  │   外部业务数据库实例（v1 唯一引擎）
         │ Driver      │
         └─────────────┘

   ┌──────────────────────────────────────────────────┐
   │  平台元数据库（PostgreSQL）：用户/权限/审计/任务/  │
   │  catalog 配置等所有平台自身数据                    │
   └──────────────────────────────────────────────────┘
```

## 2. 模块划分

| 层 | 模块 | 职责 |
|---|---|---|
| **客户端** | Web UI | 工作台、资源树、导出、审计、管理后台 |
| **网关层** | Interceptors | 认证、审计、ACL、限流（请求进出统一拦截） |
| **服务层** | API Services | 业务 RPC，按领域拆分（Instance/Database/SQL/Export/IAM/Audit/IDP/User/Setting） |
| **权限** | IAM Engine | 角色解析、权限集合判定、IAM 绑定匹配、结构化条件求值 |
| **解析** | Parser / Completion | 多语句切分、LSP 自动补全（PostgreSQL） |
| **执行** | Task Runner | 异步任务调度（导出、元数据同步、清理） |
| **元数据** | Schema Syncer | 周期性从实例同步 schema 到平台元数据库 |
| **驱动** | DB Driver / IDP | PostgreSQL 原生驱动（具体库由实现语言自选）；IdP 按协议实现（OIDC/LDAP） |

## 3. 关键设计决策

### 3.1 平台元数据库独立于业务数据库
- 系统自身需要一个**平台元数据库**（推荐 PostgreSQL），存储：用户、组、角色、IAM 策略、审计日志、任务、catalog、查询历史等。
- 用户查询/导出的数据来自**外部业务数据库**（PostgreSQL/MySQL/Oracle…），两者物理隔离。
- 平台绝不把业务数据持久化到自身（导出产物除外，且有保留期）。

### 3.2 API 定义驱动（Schema-First / OpenAPI）
- 所有 API 以 **OpenAPI 3（HTTP/JSON）** 定义为唯一事实来源（见 [12](./12-api-contract.md)），**语言/框架无关**。
- 每个操作通过 **OpenAPI 扩展**声明：
  - `x-requires-permission = "db.sql.select"`：所需权限（驱动 ACL 横切层）
  - `x-audit = true`：是否审计（驱动审计横切层）
- 好处：权限与审计声明与业务代码解耦，无法被遗漏或绕过；扩展是语言中立的元数据，由各实现的横切层（中间件 / 拦截器 / 过滤器）在请求处理前强制。

### 3.3 数据库驱动（PostgreSQL 原生）

v1 只实现 PostgreSQL，驱动按原生模块实现（PostgreSQL 协议驱动，具体库由实现语言自选），不预设多引擎插件抽象。驱动职责：

```
PostgreSQL 驱动
├── Open / Close / Ping          // 连接管理
├── QueryConn(ctx, sql, qctx)    // 查询（只读路径，Query/Export 共用）
├── SyncInstance()               // 发现实例下的库列表、版本、角色
├── SyncDBSchema()               // 反射 schema → 标准元数据结构
└── Dump(metadata)               // 导出 schema DDL/SDL
```

- 未来接入第二个引擎时，再把这些方法抽取为 `Driver` 接口——届时凭两个数据点抽象，更准确（不为尚不存在的引擎提前抽象）。

### 3.4 SQL 解析与补全
- PostgreSQL 的 SQL 解析器：多语句切分、语法诊断、自动补全（实现自选成熟的 PG 解析器）。
- 自动补全通过 **LSP over WebSocket** 暴露给前端编辑器（详见 [03-sql-query.md](./03-sql-query.md)、[12 §6.15](./12-api-contract.md)）。

### 3.5 读写连接分离与连接身份模型（DataSource）

**连接身份模型：共享服务账号。**
- 平台用**少量共享的数据库服务账号**连接业务库（一个 Instance 的 ADMIN / READ_ONLY 各一个固定账号），所有终端用户的查询都经由这个共享账号发出。
- 用户的差异化访问控制**在平台侧完成**：IAM（库/表级，结构化条件 + 环境）。v1 不做应用层脱敏，敏感列可见性由数据库授权（GRANT）决定。
- **权衡与后果**（已确认接受）：
  - ✅ 实现简单、权限完全在平台掌控、账号管理轻。
  - ⚠️ 数据库侧原生审计只能看到"平台"身份，无法精确到人 → **以平台审计日志为准**（见 [06](./06-audit-log.md)，记录完整 SQL + 操作人 IP/UA）。
  - ⚠️ 无法依赖数据库原生 RLS 做行级 → 这也是行级权限暂不纳入的原因之一。

每个 Instance 配置：
- **1 个 ADMIN 数据源**：用于元数据同步。建议只授同步所需最小权限。
- **0~1 个 READ_ONLY 数据源**：用于 SQL 工作台查询。优先使用只读连接；若无只读连接且语句只读，回退 ADMIN 连接但强制 `ReadOnly=true`（拒绝非只读语句）。

> 安全建议：即便只做查询，也优先要求每个实例配置独立只读账号，避免查询走管理员连接。

## 4. 技术选型

> 最终选型及详细理由见 [19-tech-stack.md](./19-tech-stack.md)。本节为摘要。

| 关注点 | 方案 |
|---|---|
| 后端语言 | **Go 1.25+** |
| HTTP 框架 | **chi** |
| API 协议 | **HTTP/JSON + OpenAPI 3**，手写 `openapi.yaml`，用 **ogen** 生成服务端/客户端 |
| 数据库驱动/ORM | **pgx/v5 + bun** |
| 前端框架 | **React 19 + TypeScript + Vite 8 + Tailwind CSS 4 + shadcn/ui** |
| SQL 编辑器 | **Monaco Editor** |
| 自动补全协议 | **LSP over WebSocket** |
| 平台元数据库 | **PostgreSQL 17+** |
| 元数据缓存 | 进程内 LRU（v1）；可选 Redis（v2） |
| 异步任务 | 进程内 Runner（v1），预留抽象，v2 可切 Redis + asynq |
| 密钥管理 | 应用层 AES-256-GCM + 主密钥（环境变量/KMS）；可选外部 Secret Manager |
| 身份集成 | 内置 OIDC/LDAP |
| Monorepo | 简单目录结构，不用 Turborepo/nx |
| 部署 | **Docker Compose**（v1 唯一方式） |

## 5. 部署形态

- **定位**：**单组织自部署**（self-hosted，面向一个公司内部使用）。系统中的 Workspace 退化为**单一固定实例**，不做多租户隔离与计费席位。
- **部署形态**：单机 Docker / 单节点二进制 + 平台 PG 即可满足；未来如需更高可用可演进到多副本 + 主从。
- 所有数据库连接凭据加密存储，强烈建议对接外部 Secret Manager。

## 6. 安全边界

1. 平台进程持有的数据库连接凭据，在内存中按需解密、用后即清。
2. 查询/导出路径必须在服务端完成权限校验（IAM + 项目隔离 + 环境），前端只展示经授权可访问的数据。
3. 审计日志写入使用「不可取消的 context」，确保即使客户端断开，审计仍落库。
4. 所有对外连接（到业务 DB、到 IdP）均要求 TLS；支持 SSH 隧道/跳板机接入业务库。

## 7. 关键模块协作（以一次查询为例）

```
用户在编辑器执行 SELECT
  → 客户端调用 POST .../databases/{d}:query 操作
  → 认证横切层：校验 JWT/会话
  → ACL 横切层：检查粗粒度权限 db.sql.select（IAM 绑定匹配 + 项目隔离）
  → SQL Service:
      1. resolveDataSource → 取只读连接
      2. 多语句切分 → 逐语句
      3. 细粒度权限校验（结构化条件，库/表级 + 环境）
      4. 行数/超时上限校验
      5. 调用驱动执行查询（只读，语句超时保护）
      6. 写查询历史
  → 审计横切层：记录 :query 操作（含语句摘要、库表、耗时、状态）
  → 返回结果给前端
```
